# AI 浏览器遇到验证码和弹窗：**为什么它不该替你点「确定」**

> 长尾定位：搜「dsh 浏览器 验证码」「AI 自动化 弹窗 确认」的人，担心的就是这件事。
> 结论先行：**靠提示词自觉是不够的** —— 模型看不见的 `confirm()` 依然会被"接受"，
> 所以这件事必须在**接口层**拦住：挂起、阻断、上报、等一个显式回答。

## 问题长什么样

网页上 `alert` / `confirm` / `prompt` / `beforeunload` 是**原生对话框**：它们不属于页面 DOM，
截不到、点不着，而且很多自动化栈的默认行为是 —— **自动接受**。

于是一个「让 AI 帮你删掉这条记录」的请求，可能在你看不见任何确认框的情况下，**真的删了**。

## 我们的做法：弹窗是机制级，挑战页是「识别 + 交还给你」

| 环节 | 行为 |
|---|---|
| 弹窗出现 | **挂起**：不 accept、不 dismiss，登记成一个 pending 状态 |
| 这一页还能不能动 | **不能**：其它工具一律拒绝（返回 `DIALOG_PENDING` 并说明在等谁） |
| 模型看到什么 | 快照不再描述页面，而是描述**阻塞者**：「有个 confirm，内容是 X，尚未接受也未取消」 |
| 谁来回答 | 只有一次显式的 `browser_dialog({ accept })` —— **由用户或用户授权的调用方**决定 |
| 验证码 / 挑战页 | **不是同一档**：识别出来后在结果里加提示，让模型停下来把窗口交给你；没有任何代码阻止它继续点 |
| 登录 / 2FA | **更没有机制**：插件没有专门的探测器，靠模型从快照看出"这是登录页"并停下来（提示词层面的纪律，见 `codex-rules.md`） |

上面「谁来回答」那几行写在 [`DIALOG-POLICY.md`](../../DIALOG-POLICY.md)，并且有测试覆盖
（场景测试里有真实 `confirm()` 的旅程：挂起 → 其它工具被拒 → 显式取消 → 页面继续）。
挑战页那一行是另一套机制，见下一节；它的完整边界在 [`SECURITY.md`](../../SECURITY.md)。

## 但"停下来"要先"认得出来"：三层机器信号 + 一层行为兜底

上表最后一行（验证码停下来）成立的前提，是**先认出这一页是拦截面**。这里最常见的做法是
枚举页面上的关键词 —— 也是最容易烂的做法。FlareSolverr 就是这么做的，然后翻车了：
上游 issue #1734 里，报问题的人自己诊断出「拦截页把自己的 class 和 id 改了，所以现有的
检测规则失效」，而且它连页面标题都依赖（语言一变就废）。

所以我们按**稳定性**排序，而不是按覆盖率：

| 层 | 判什么 | 为什么可信（以及当前的门槛） |
|---|---|---|
| 1 | 主文档响应的**响应头**：`cf-mitigated: challenge`、`x-amzn-waf-action: challenge`、`x-iinfo`、`x-datadome*` | 这是厂商对外的 API —— Cloudflare 专门发文教用户读 `cf-mitigated`。`x-iinfo` / `x-datadome*` 对每个响应都挂，所以必须状态码同时是 **403 / 429 / 503** 才算；`cf-mitigated` 的值必须是 `challenge` |
| 2 | 厂商**控件自己的无障碍名**：reCAPTCHA / hCaptcha / Turnstile / Arkose / PerimeterX 的 iframe 标题就是他们的产品名 | 是他们自己的东西。只认 `iframe` / `frame`（厂商控件就是 iframe），只在页面**几乎不能操作**时才算数（可点元素 ≤12，否则那是正常页脚上的 v3 徽标）；控件层会往树里扫到 **8 层**深，因为真实 hCaptcha 的 iframe 常被包装层挡住 |
| 3 | **文案**（最后手段）：标题里的 `安全验证` / `Just a moment...`，或控件上的命令式文案（`请输入验证码`、`拖动滑块完成拼图`） | 最脆，所以只当补充。标题层只在页面**几乎没得点**时生效（可点元素 ≤5，否则搜"安全验证"的结果页也会中招）；控件文案只认 ≤32 字符的短标签，并排除 `获取验证码` / `发送验证码` 这类正常登录控件 |

三层都没认出来时，**不猜厂商**，改问一个与厂商无关的问题：**这个动作之后，页面变了吗？**

如果动作前后 URL、标题、元素集合完全一致，就在这次结果里附一句「没有可见变化」，让模型先自己确认、然后停手问人。触发条件有两条：页面**几乎空**（可点元素 ≤3）时**一次**不变就够；页面**有内容**时要**连续两次**一模一样，这样普通的一次"点了不该有变化"的点击不会误报。这一层不认识任何厂商，所以**新出现的验证方式也能被它接住** —— 代价只是多问用户一句，而不是拿账号去撞墙。

除了行为兜底，还有两种"看起来像墙"的页面不会一句话都没有：

- `[http NNN]`：主文档是非 2xx（且没有识别成挑战页），后面这棵树可能是错误页或拦截页；
- `[nothing here]`：一个可点元素都没有、也几乎没有文字 —— 访客校验、还在加载、或者需要人。

漏识别的代价是**少一句提示**，而不是"被当成正常页继续猛点"：零可点的静默页有 `[nothing here]`、非 2xx 有 `[http NNN]`、动作无效有行为兜底，三层都指向"停下来问人"。新增一家厂商 = 在 [`src/challenge-signatures.ts`](../../src/challenge-signatures.ts) 加一条签名，
再在 [`tests/challenge.test.ts`](../../tests/challenge.test.ts) 加一条用例 —— 判定逻辑本身不用改。

## 为什么不是"提示词里写一句别乱点"

因为**提示词是建议，接口是事实**。我们甚至在文档里直接对比过：

- 提示词级：「请你不要自动接受对话框」→ 一次误判就穿透；
- 机制级：**接口层面拿不到"接受"这个动作**，除非显式调用 —— 不存在"不小心"。

## 顺带一个同源的设计：旧 ref 不许"猜"

同一套哲学：页面重渲染后，旧 ref **不会**去匹配"看起来像"的新元素，而是**快速失败并说明原因**，
让模型重新快照。宁可多一步，也不静默点到别的东西上。

（这条在 0.4.5 之前**确实出过问题**：智能模式按位置把 ref 贴到无障碍树上，页面上有隐藏元素时
整体错位，`ref` 会指向另一个元素。修法 + 57 项验收（npm 安装形态下跳过 1 项）里的端到端用例见 CHANGELOG 0.4.5/0.4.7。）

dsh plugin --profile web add github:miqian-nomad/dsh-browser-playwright-codex
