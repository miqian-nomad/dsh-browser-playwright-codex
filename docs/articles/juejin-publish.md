## 想让 AI 帮你上网页办事，卡在哪

如果你不敢把账号交给一个自动化脚本，这篇写给同类人。它不需要你的密码，你自己登录一次就够。

我最初的需求很小：让 AI 帮我登录后台查个数据、填个表、抓个列表。真做起来撞到五堵墙。

1. **登录态。** 每次开一个全新浏览器环境，等于每次都要重新登录；把账号密码写进脚本更不可能。
2. **验证码和原生弹窗。** `alert/confirm` 不属于页面 DOM，不少自动化栈的默认行为是自动接受。于是「帮我删掉这条记录」可能在你看不见确认框的情况下真的删了。
3. **窗口抢焦点。** 有头模式下你明明最小化了，它过一会儿自己跳回你眼前。
4. **点了没反应。** 它说点了，页面没变。你以为是网络慢，实际是它点到了另一个元素。
5. **看不见它做了什么。** 拦不住，也不敢把登录态交出去。

这五条都是机制层面的问题，多写几句提示词改不了。

## 这个东西做了什么

我做了个浏览器插件，跑在 DeepSeek Harness（DSH）上。它让 agent 使用你已经登录的账号，在真实网页上填表、抓取列表、多标签查后台。窗口开在你自己的桌面上，带独立的浏览器 profile。安装一行命令：

```sh
dsh plugin --profile web add github:miqian-nomad/dsh-browser-playwright-codex
```

五个痛点对应五处实现。

**登录态。** 持久 cookie 留在 profile 里；会丢的是会话 cookie，也就是关窗即忘的那类。插件在关窗前把登录态导出，下次启动回注，重启 DSH 之后仍然是登录状态。你自己登录一次，插件借用这个状态，不需要你的密码。

**窗口不抢焦点。** 有头模式下窗口自己跳出来，有三个独立根因，都定位到了源码：切标签时会无条件把窗口拉到前台；新建标签时 Chromium 自己就会激活窗口；导出登录态时 Playwright 还会开一个临时页面。第三条最隐蔽，窗口被拉起来的原因是它在保存登录态。

**遇到登录、验证码、弹窗会停下来。** 原生对话框被挂起后，这一页的其它操作全部被阻断；模型收到的是「有个 confirm，内容是 X，尚未接受也未取消」，只有一次显式回答才能结清。这个限制来自接口设计，加提示词改不了，所以不存在「不小心点了确定」。

**旧引用宁可报错也不猜。** 页面重渲染后，旧 ref 不会去匹配一个看起来像的新元素，而是快速失败并说明原因，让模型重新取快照。这条我们踩过坑：早期版本按位置把元素引用贴到无障碍树上，页面上只要有隐藏元素就会整体错位，快照说输入框是 A，而 A 其实是一个隐藏链接。修完之后，验收里加了一个端到端用例，把隐藏元素故意排在按钮前面。

**安全边界默认收紧。** 两个强力工具（在页面里执行任意 JS、原始 CDP）在包里默认关闭，关着时工具根本不注册。CDP 采用默认拒绝加显式方法清单，只放行只读检查与四个点名的输入事件，`Input.` 家族不放开。URL 白名单覆盖所有能导航的路径。不伪造浏览器指纹，只做减法。不向外发送任何数据。
