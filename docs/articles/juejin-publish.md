## 一、先说痛点：想让 AI 帮你上网页办事，卡在哪

「让 AI 帮我登录后台查个数据 / 填个表 / 抓个列表」——听起来很简单，真做起来，几乎每个人都会撞到同样几堵墙：

1. **登录态是最大的门槛。** 最常见的做法是每次开一个全新浏览器环境，等于每次都要重新登录；把账号密码写进脚本？没人敢。
2. **它跑到一半遇到验证码或原生弹窗。** `alert/confirm` 这类对话框不属于页面 DOM，很多自动化栈的默认行为是**自动接受** —— 于是"帮我删掉这条记录"可能在你看不见任何确认框的情况下真的删了。
3. **窗口老抢你的焦点。** 有头模式下你明明最小化了，它过一会儿自己跳到你眼前。
4. **最怕的不是报错，是"静默点错"。** 它说点了，页面没变；你以为是网络慢，其实是它点到了另一个元素。
5. **你没法确认它到底在你的账号里做了什么。** 看不见、拦不住、也不敢交。

这些**基本都是机制问题**，不是"提示词里多叮嘱几句"能解决的。

## 二、我做的这个东西：一个"你自己的浏览器"插件

我做了个 DeepSeek Harness（DSH）的浏览器插件：**让 agent 用你已经登录的账号，在真实网页上填表、抓取列表、多标签查后台。**

它跑在**你自己桌面上一个可见的窗口**里，带**独立的浏览器 profile**。装它只要一行：

```sh
dsh plugin --profile web add github:miqian-nomad/dsh-browser-playwright-codex
```

针对上面五个痛点，它是这么处理的：

**① 登录态：登录一次，一直记得（而且不需要交出密码）**

持久 cookie 本来就留在 profile 里；真正会丢的是**会话 cookie**（关窗即忘的那类）。所以关窗前会把登录态导出、下次启动回注 —— 重启 DSH 之后仍然是登录状态。**你本人登录一次，它只借用这个状态，永远不需要你的密码。**

**② 窗口是你的，最小化就不吵你**

有头模式"自己跳出来"其实有**三个独立根因**，我们全部追到了源码并修掉：切标签时的无条件窗口激活、新建标签时 Chromium 必激活窗口、以及导出登录态时 Playwright 会**开一个临时页面**（最隐蔽的一条 —— 你以为"它自己跳"，其实是它在保存登录态）。

**③ 遇到登录、验证码、弹窗：停下来等你，绝不替你点「确定」**

原生对话框会被**挂起**：这一页的其它操作全部被阻断，模型收到的是"有个 confirm，内容是 X，尚未接受也未取消"，只有一次**显式回答**才能结清。
这是**接口层面**的限制，不是"提醒模型别乱点" —— 所以不存在"不小心点了确定"。

**④ 宁可报错，也不静默点错元素**

旧引用（ref）不会去"猜"一个看起来像的新元素，而是**快速失败并说明原因**，让模型重新取一次快照。
这条我们真的踩过坑：早期版本按位置把元素引用贴到无障碍树上，页面上只要有隐藏元素就会**整体错位** —— 快照说"输入框是 A"，而 A 其实是个隐藏链接。修完之后我们在验收里加了一个"把隐藏元素故意排在按钮前面"的端到端用例，专门盯着这类问题。

**⑤ 安全边界写在明处，而且默认是收紧的**

- 两个"强力工具"（在页面里执行任意 JS、原始 CDP）**包里默认关闭**，关着时**工具根本不注册**（不是"注册了但拒绝"）；
- CDP 采用**默认拒绝 + 显式方法清单**：只放行只读检查与四个点名的输入事件（连 `Input.` 家族都不放开）；
- URL 白名单覆盖所有能导航的路径；不伪造浏览器指纹（只做减法）；**不向外发送任何数据**。
